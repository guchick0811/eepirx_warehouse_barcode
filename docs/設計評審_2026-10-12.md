# 倉儲掃碼查詢 APP — 設計評審（2026-10-12）

評審依據：design-critique（五面向）、accessibility-review（WCAG 2.1 AA）、Apple 設計原則（回應、直接操作、可及性、八大原則）、Emil Kowalski 設計工程（動態與細節）。
使用情境：倉庫員工單手持機、可能戴手套、光線不佳、一天要掃數十到數百次。

## 整體印象

資訊階層正確：結果頁一眼就看到儲位與庫存，掃描頁相機佔主視覺，底部導覽清楚。最大的機會在「連續掃描的節奏」——每掃一件要離開相機頁、再按鈕回來、相機重新啟動約 1 秒，對一天掃上百次的人來說是最明顯的摩擦。其次是深色主題下幾個對比度不足的地方，在倉庫光線差時會更吃力。

## 評分摘要

| 面向 | 狀態 | 一句話 |
|---|---|---|
| 可用性 | 🟡 | 核心流程順，但連續掃描要多一步、相機重啟慢 |
| 視覺階層 | 🟢 | 儲位／庫存放大正確；名稱字級可再加強 |
| 一致性 | 🟡 | 按鈕尺寸有 40 / 44 / 52 三種；emoji 圖示跨平台外觀不一 |
| 可及性 | 🔴 | 主按鈕文字對比 2.77:1、輸入框邊框 1.41:1，皆不及格 |
| 動態與回饋 | 🟡 | 掃到有震動＋聲音很好；按鈕無按壓回饋；未處理減少動態偏好 |

## 做得好的地方

- 結果頁把儲位、庫存放大、庫存 0 變紅、已停用有徽章：倉庫最需要的三個判斷一眼完成。
- 掃到條碼同時震動＋短音＋狀態列顯示讀到的值：三種回饋同一幀發生，符合「因果、同步、節制」。
- 同一條碼多商品先列清單、查無資料給出下一步建議：沒有死路。
- 底部導覽文字＋圖示、安全區域（瀏海、Home 指示條）皆有處理。
- 懸浮掃描鈕在拇指區、76px 大小適合戴手套。
- 所有資料以 `textContent` 寫入、CSP 限制外連：工藝與責任感兼具。

## 建議優先順序

1. **連續掃描底部面板（#3）** — 影響每一次掃描的節奏，是唯一能讓員工「感覺快很多」的改動。相機不關、面板滑入約 250ms、下一件直接覆蓋。
2. **對比度三處（#1、#2、#10）加觸控尺寸（#4）** — 一次性 CSS 調整，半小時內完成，直接解決倉庫光線差與戴手套的問題。
3. **按壓回饋與減少動態（#5、#8、#15、#16）** — 純 CSS，讓整體手感從「網頁」變成「APP」。
4. **SVG 圖示、表單標籤、密碼重設表單（#6、#7、#9）** — 一致性與可及性收尾。
5. 其餘（#11～#14）視時間處理。

## 補充觀察（非缺陷，供決策）

- 深色主題在室內倉庫合理；若有戶外卸貨區，可考慮跟隨系統的淺色模式（`prefers-color-scheme`），目前程式已把顏色集中在變數，加一組淺色值即可。
- 若未來配發藍牙條碼槍，掃描頁的手動輸入框保持焦點即可直接接收輸入並以 Enter 送出，不需改架構。
